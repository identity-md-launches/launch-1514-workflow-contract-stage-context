# Contract ABI and integration guide

Authoritative ABI exports are [LaunchToken.json](abi/LaunchToken.json) and [JobZero.json](abi/JobZero.json). They include constructors, functions, events, tuples, and custom errors generated by Solidity 0.8.26 from the delivered source. Rebuild/check with `python3 scripts/export_abi.py --check`; regenerate with the same command without `--check`.

## LaunchToken

The constructor has no arguments. Standard ERC-20 functions are `name`, `symbol`, `decimals`, `totalSupply`, `balanceOf`, `allowance`, `approve`, `transfer`, and `transferFrom`. Name is `Teyo`, symbol is `TEYO`, decimals is 18, and total supply is `10**27` minor units. Transfers return `bool` and use the standard `Transfer` and `Approval` events and ERC-6093 custom errors. There are no optional administrative, burn, mint, permit, or upgrade functions.

## JobZero writes

All writes are nonpayable; send zero ETH. Read the relevant state immediately before preparing a transaction and handle a changed run, expired deadline, or changed worker as a possible revert.

| Function | Caller and requirements | Token movement |
| --- | --- | --- |
| `setToken(address token_)` | Immutable owner, exactly once; deployed 18-decimal token. | None. |
| `open()` | Anyone; token set, no open run. | Collect 10,000 TEYO from caller. |
| `handoff(address to)` | Current worker, before deadline; new nonzero worker for this run. | Collect current fee from caller, burn floor(fee/2), retain remainder in bounty. |
| `timeout()` | Anyone, when deadline reached. | Burn solo bounty or equal-share remainder; reserve beneficiary shares. |
| `claim(uint256 runId)` | An earlier worker in a closed run who has not claimed. | Transfer one equal share to caller. |
| `goOnline()` | An address that has neither held nor joined this unexpired run. | Collect and burn 10 TEYO from caller. |
| `goOffline()` | Online member of the still-open run. | None; no refund. |

Approve **the JobZero contract as spender**, using the configured TEYO contract. Use `OPEN_FEE()`, `handoffFee()`, or `ONLINE_FEE()` for the exact amount; avoid unnecessary unlimited approvals. A handoff recipient needs no allowance until they choose to hand off. `timeout`, `claim`, and `goOffline` need no allowance.

## State, tuples, and page order

All numeric fields below are `uint256` except attempt status, which ABI-encodes as `uint8`. Times are Unix seconds. Token amounts are minor units.

| View | Meaning |
| --- | --- |
| `owner()`, `token()` | Explicit owner and configured token. The token is initially unset. |
| `currentRun()`, `isOpen()` | Latest run ID and whether it still awaits settlement. |
| `worker()`, `deadline()`, `handoffFee()` | Current worker and expiry, or zero when closed; next fee, or initial fee when closed. |
| `runs(uint256)` | `Run` tuple below; all default values for an unknown ID. |
| `workerStats(address)` | `(attempts, handoffs, totalEarned, timesFailed)` across every run. Earned means claimed. |
| `hasHeld(uint256,address)` | Whether the address ever held the job in that run. |
| `claimable(uint256,address)`, `claimed(uint256,address)` | Available share (zero for ineligible/unknown/claimed) and completed-claim flag. |
| `getAttempts(uint256,uint256,uint256)` | `Attempt[]`, newest first. |
| `getQueue(uint256,uint256,uint256)` | Active `QueueEntry[]`, newest first; empty for closed/unknown run. |
| `queueLength(uint256)`, `isOnline(uint256,address)` | Live queue size/membership; zero/false for closed/unknown run. |
| `hasJoinedQueue(uint256,address)` | Historical one-entry eligibility consumed, even after leaving/closure. |
| `longestRun()` | `(runId, duration)` including effective live elapsed time. `(0,0)` before any run. |
| `biggestBounty()`, `mostHandoffs()` | Greatest gross bounty / completed handoffs in any single run. |
| `totalBurned()`, `totalLiability()` | TEYO sent by JobZero to the burn address / active and unclaimed obligations. |

The public constants are `OPEN_FEE`, `INITIAL_HANDOFF_FEE`, `ONLINE_FEE`, `WORKER_WINDOW`, `MAX_PAGE_SIZE`, and `BURN_ADDRESS`.

`Run` fields in declaration order:

```text
(uint256 attempts, uint256 bounty, uint256 fee,
 uint256 openedAt, uint256 closedAt, address failedWorker,
 address worker, uint256 deadline, uint256 share,
 uint256 claimedCount, bool closed)
```

`bounty` stays at the gross funded amount after settlement and claims. `share` is fixed at timeout. `fee` is the next handoff fee, frozen after closure. `worker` stays the final worker in closed run records. `closedAt` is when timeout was executed; `deadline` is the effective failure time. `attempts` includes the opener and the failed final worker.

`Attempt` fields: `(address worker, uint256 startedAt, uint256 endedAt, uint8 status)`. Status values are **0 Holding**, **1 HandedOff**, **2 Failed**. `endedAt` is zero while holding, the handoff timestamp after a handoff, or the deadline upon timeout. Before timeout is mined, an overdue holding attempt still has status 0; the UI should derive its overdue state from the current deadline.

`QueueEntry` fields: `(address worker, uint256 onlineAt)`. Both pagination functions use `(runId, start, count)`, where `start` is a zero-based offset into the newest-first sequence, **not** an attempt ID or timestamp. `count > 100` reverts; zero or out-of-range offsets give an empty page. Results shrink at the end. Pin a block for multipage queries to avoid offsets shifting during handoffs/queue activity.

## Events and indexing

| Event | Indexed fields | Other fields |
| --- | --- | --- |
| `TokenSet` | `token` | — |
| `Opened` | `runId`, `worker` | `deadline`, `bounty` |
| `HandedOff` | `runId`, `from`, `to` | `fee`, `attempt` |
| `TimedOut` | `runId`, `failedWorker` | `attempts`, `bounty` |
| `Claimed` | `runId`, `worker` | `amount` |
| `Online` | `runId`, `worker` | `onlineAt` |
| `Offline` | `runId`, `worker` | — |
| `Burned` | `runId` | `amount` |

`HandedOff.attempt` is the recipient's **one-based** attempt number: the first handoff emits 2. `HandedOff.fee` is the amount just paid; the view returns the new fee. `TimedOut.bounty` is the gross bounty before rounding. `Burned` covers queue payments, handoff burns, solo burns, and settlement dust. `totalBurned` excludes direct token transfers others make to the dead address.

An automatic queue removal emits `Offline` before `HandedOff`. `TimedOut` invalidates every remaining queue entry in that run without per-wallet events. An indexer must mark those entries inactive. Failed worker histories come from `TimedOut`; claim opportunities come from the wallet's `Opened`/incoming `HandedOff` events, validated with `claimable`. Process logs by block/transaction/log order and handle chain reorgs. Emit effects and token transfers are atomic: reverted transactions contain no committed event history.

## Errors

The generated ABI lists all error signatures. Main application errors are:

| Errors | Meaning |
| --- | --- |
| `InvalidOwner`, `Unauthorized` | Bad deployment owner or nonowner configuration call. |
| `TokenNotConfigured`, `TokenAlreadySet`, `InvalidToken` | Token setup is missing, already locked, or fails code/decimals checks. |
| `RunAlreadyOpen`, `NoOpenRun` | Action incompatible with current run state. |
| `NotWorker`, `InvalidRecipient`, `AlreadyHeld` | Handoff caller/recipient or queue worker eligibility invalid. |
| `DeadlinePassed`, `DeadlineNotReached` | Wrong side of the exact deadline boundary. |
| `AlreadyJoined`, `NotOnline` | Queue lifetime entry consumed, or leaving without active membership. |
| `NothingToClaim` | Unknown/unclosed run, failed/nonparticipant, or already claimed. |
| `PageTooLarge` | `count` exceeds 100. |
| `UnexpectedTokenAmount` | Incoming balance increase differs from the full fee. |
| `ReentrancyGuardReentrantCall` | Attempted nested mutation. |
| `SafeERC20FailedOperation` | Token reported transfer failure. |

SafeERC20 also bubbles underlying token errors. Decode TEYO's ERC-6093 errors with its ABI for insufficient balance/allowance. No raw wallet keys, signing services, environment values, or deployment addresses are included in ABI exports.
